# Scene Studio

대본을 의미·행동·장소·감정·시각적 변화 기준으로 분석하고, 검토한 장면별 프롬프트로 이미지를 병렬 생성하는 로컬 앱입니다. Node.js 표준 라이브러리만 사용하며 `npm install`이 필요하지 않습니다.

## 실행

- Node.js 22 이상과 ChatGPT에 로그인된 최신 Codex CLI가 필요합니다. Claude 분석이나 OpenAI API 이미지 생성만 쓸 경우 아래 **AI 서비스 선택**을 참고하세요.
- macOS: `시작.command`를 더블클릭합니다.
- 터미널: 이 폴더에서 `npm start` 실행 후 <http://127.0.0.1:4317> 접속합니다.
- 종료: 실행한 터미널에서 Ctrl+C.
- 연결 문제가 있으면 `codex login status`로 확인하고 `codex login`으로 로그인합니다. 앱은 로그인 토큰을 읽거나 복사하지 않고 설치된 공식 CLI에 인증을 맡깁니다.

### AI 서비스 선택 (⚙ AI 설정)

상단의 **⚙ AI 설정**에서 장면 분석과 이미지 생성 서비스를 각각 고를 수 있습니다. 진행 중인 작업은 시작할 때의 설정을 유지합니다.

| 단계 | 선택지 | 인증 |
| --- | --- | --- |
| 장면 분석 (텍스트) | ChatGPT · Codex (기본) | `codex login` |
| | Claude (`sonnet`/`opus`/`haiku`) | Claude Code CLI의 OAuth 로그인 (`claude auth login`) |
| 이미지 생성 | ChatGPT · Codex 이미지 도구 (기본, 모델 자동 선택) | `codex login` |
| | OpenAI API · `gpt-image-2.5-flare`(기본, 빠름) / `gpt-image-2.5-sunburst`(정밀) | OpenAI API 키 |

- **Claude**: 설치된 공식 Claude Code CLI에 인증을 맡기며 앱은 토큰을 읽거나 저장하지 않습니다. 구독 로그인을 쓰도록 `ANTHROPIC_API_KEY`는 CLI에 전달하지 않습니다. 실행 파일은 PATH, `~/.claude/local`, `~/.local/bin`, Homebrew, Claude 데스크톱 앱에 포함된 CLI 순으로 찾으며 `CLAUDE_BIN`으로 지정할 수 있습니다. Claude는 이미지를 만들지 않으므로 이미지 생성은 Codex 또는 OpenAI API를 사용합니다.
- **GPT 모델 확인·선택**: AI 설정의 **GPT 모델 (대본 분석 · 이미지 작업 지시)**에서 모델을 선택합니다. 설치된 Codex의 공식 `model/list`를 조회하며 목록을 새로고침하거나 모델 ID를 직접 입력할 수도 있습니다. 기본 모델을 선택하면 조회한 `isDefault` 모델을 표시하고, 실행 시에도 그 ID를 명시합니다. 조회 실패 시 기본 모델을 추측해 실행하지 않고 직접 지정하도록 안내합니다. 프로젝트 대본 아래에는 현재 설정과 최근 분석에 사용한 모델이 표시되며, 결과는 `analysisRun`에 기록됩니다. ChatGPT 이미지 도구를 호출하는 GPT에도 같은 설정이 적용됩니다. 실제 그림을 그리는 이미지 모델은 별도 설정입니다. [공식 모델 조회 문서](https://learn.chatgpt.com/docs/app-server#list-models-modellist).
- **OpenAI API**: 참고 이미지가 없으면 `/v1/images/generations`, 있으면 `/v1/images/edits`(최대 16장)를 호출합니다. 품질은 `auto`~`max`, 크기는 화면 비율에 맞춰 16:9 2048×1152, 9:16 1152×2048, 1:1 1024×1024, 4:3 1536×1152로 요청합니다. 키는 `data/secrets.json`(권한 600)에만 저장되며 `/api/state`, 내보내기, 화면에 노출되지 않습니다. 저장된 키가 없으면 `OPENAI_API_KEY` 환경 변수를 사용합니다. 폴더를 통째로 옮기면 키도 함께 복사되므로 공유 전에 설정에서 **저장된 키 삭제**를 누르세요. 사용량은 API 계정에 과금됩니다. `OPENAI_BASE_URL`로 호환 엔드포인트를 지정할 수 있습니다.

Codex 실행 파일은 `CODEX_BIN`으로 바꿀 수 있습니다. GPT 모델 우선순위는 **AI 설정에서 선택한 모델 → `SCENE_CODEX_MODEL` 환경 변수 → 공식 모델 목록의 기본 모델**입니다. 사용자 Codex 설정 파일의 모델 선택은 생성 작업에 적용하지 않습니다. PATH와 `/Applications`, 사용자 Applications 폴더에서 현재 및 이전 ChatGPT/Codex 앱의 CLI 위치를 찾습니다. 앱 기본 포트는 4317, 데이터 폴더는 `data/`이며 `PORT`, `SCENE_DATA_DIR`로 변경할 수 있습니다. 참고 이미지 폴더는 실행 파일 옆의 `참고이미지/`입니다(`SCENE_REFERENCE_DIR`로 별도 지정 가능).

### 다른 Mac으로 옮기기

- `시작.command`, `data/`, `참고이미지/`를 포함한 **프로젝트 폴더 전체**를 옮기세요. `data/`만 백업하면 새 참고 이미지는 포함되지 않습니다.
- 참고 이미지를 앱에서 등록하면 `참고이미지/`에 저장됩니다. 저장된 경로는 상대 경로이며, 실제 생성 시 현재 폴더를 기준으로 절대 경로를 계산합니다. 폴더 이름이나 사용자 이름이 달라져도 기존 이미지를 사용할 수 있습니다.
- 기존 버전의 `data/references/` 이미지는 첫 실행 시 `참고이미지/`로 자동 복사됩니다. 이전 이미지와 데이터 백업은 보존합니다. 파일 없이 경로만 남아 있으면 해당 이미지를 다시 등록해야 합니다.
- 새 Mac에도 Node.js 22 이상과 공식 ChatGPT/Codex CLI가 필요하며, **그 Mac에서 본인의 ChatGPT 계정으로 로그인**해야 합니다. 로그인 토큰은 이 프로젝트에 포함하지 않습니다.
- Finder 실행에서도 Apple Silicon/Intel Homebrew 설치 경로를 찾고 Node.js 버전을 검사합니다. 다른 프로그램이나 다른 폴더의 Scene Studio가 기본 포트를 사용하면 시작 도우미가 4318~4337 중 빈 포트로 실행합니다. 같은 폴더의 앱이 이미 실행 중이면 해당 화면을 다시 엽니다.

### macOS가 시작.command를 차단하는 경우

AirDrop이나 다운로드로 옮기면 macOS가 파일에 보안 표시를 다시 붙일 수 있습니다. 현재 파일에서 표시를 해제해도 다른 Mac의 승인이 자동으로 이어지는 것은 아닙니다. 새 Mac에서는 `시작.command`를 한 번 열어 본 뒤 **시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기**를 선택하세요. [Apple 공식 안내](https://support.apple.com/ko-kr/102445).

또는 터미널에서 `/bin/zsh `를 입력하고 `시작.command` 파일을 터미널로 드래그한 뒤 Enter를 누르면 해당 스크립트를 실행할 수 있습니다. 실행 권한이 전달되지 않은 경우에도 이 방법을 쓸 수 있습니다. macOS 전체의 보안 기능을 끌 필요는 없습니다.

## 사용 흐름

1. 프로젝트 이름, 대본, 화면 비율, 꼭 지킬 조건을 입력합니다.
2. **캐릭터 추가 · 시트 첨부**에서 이름·외형 설명과 PNG/JPEG/WebP 파일을 함께 등록합니다. 정면·측면·뒷모습·표정이 모인 시트도 한 장 그대로 첨부합니다. 카드의 **편집**으로 설명·첨부를 수정할 수 있습니다. 시트가 없으면 **설명으로 시트 만들기** 또는 캐릭터 카드의 **설명으로 시트 생성**을 사용합니다. 일반 이미지와 시트 합계 캐릭터당 최대 10장, 파일당 32MB이며 추가·편집 창에서는 한 번에 합계 32MB까지 지원합니다.
3. **AI 장면 분석**을 누릅니다. 원문 누락·중복을 검사하며, AI가 등장인물을 판단해 등록된 캐릭터 ID를 연결합니다.
4. 장면 제목, 원문 구간, 프롬프트, 등장 캐릭터 체크박스, 장면 스타일을 수정합니다. 장면은 원문 구절 기준 분할 또는 다음 장면과 병합할 수 있습니다. 분할·병합 후 프롬프트를 해당 장면에 맞게 다듬어 주세요. 저장 시 전체 원문이 순서대로 보존되는지 검사합니다(공백 차이 허용).
5. **최종 프롬프트**에서 실제 전달할 내용을 확인합니다. **미생성 / 실패 장면 생성** 또는 개별 **생성**을 누릅니다.
6. 최대 3개 작업이 동시에 실행되고 일시적인 오류는 최대 2회 재시도합니다. 완료 후 개별 재생성, 이전 이미지 버전 선택, 다운로드가 가능합니다. 프롬프트/스타일/제약을 변경한 장면도 새 생성 대상으로 표시됩니다.

생성이 진행 중인 프로젝트 편집은 잠기지만 다른 프로젝트는 사용할 수 있습니다. 앱이 재시작되면 중단된 작업은 실패로 표시하고 사용자가 재시도할 수 있습니다. 이전 이미지 파일은 유지합니다. 대본을 다시 분석하면 현재 장면 목록은 새 분석 결과로 교체됩니다.

### 설명으로 캐릭터 시트 생성

1. 캐릭터 이름과 원하는 외형을 입력하고 **저장하고 시트 만들기**를 누릅니다. 기존 캐릭터는 카드의 **설명으로 시트 생성**을 누릅니다.
2. 외형 설명, 프로젝트 기본 스타일 적용 여부, 추가 화풍 설명을 확인합니다. 기존 캐릭터 참고 이미지는 외형 유지에 함께 사용됩니다. **생성 프롬프트 확인**에서 최종 프롬프트와 GitHub 출처를 볼 수 있습니다.
3. **시트 생성 · 자동 등록**을 누르면 현재 이미지 생성 설정으로 4:3 시트를 만듭니다. 정면·측면·뒷모습, 표정, 의상 세부, 색상표를 요청합니다.
4. 완료된 이미지는 `참고이미지/`에 저장되고 캐릭터의 `character-sheet` 참고 이미지로 자동 등록됩니다. 카드에서 크게 보기와 다운로드가 가능합니다. 해당 캐릭터가 등장 인물로 선택된 장면을 다음에 생성할 때 자동 전달됩니다. 기존 장면 이미지는 보존하며 해당 장면을 생성 필요로 표시합니다.

시트 제작 중에도 다른 캐릭터를 추가·편집·첨부하고 시트 생성 요청을 계속 대기열에 올릴 수 있습니다. 최대 3개를 동시에 생성하며, 나머지는 요청 순서대로 대기합니다. 캐릭터 영역에 생성 중·대기 개수가 표시됩니다. 생성 중이거나 대기 중인 캐릭터 자신의 수정·삭제·중복 생성은 완료까지 잠기며, 다른 캐릭터의 작업에는 영향을 주지 않습니다. 대본 분석과 장면 생성은 시트 작업이 모두 끝난 뒤 진행합니다.

프롬프트는 [ZeroLu/awesome-gpt-image의 Official Character Reference Sheet](https://github.com/ZeroLu/awesome-gpt-image#official-character-reference-sheet)를 번들로 포함하고, 사용자 외형·일관성·화풍 지시를 덧붙입니다. 원문과 출처는 `lib/character-sheet.mjs`, 귀속·라이선스는 `THIRD_PARTY_NOTICES.md`에 있습니다. 실행 중 GitHub에서 프롬프트를 다시 다운로드할 필요는 없습니다. 시트와 장면은 동일한 생성 대기열(동시 3개, 일시 오류 재시도 2회)을 사용합니다. 실패하면 오류를 카드에 표시하며, 참고 이미지가 이미 10장이면 추가 시트를 생성하지 않습니다.

## 긴 대본 편집

스토리보드는 **집중 편집**과 **전체 보드**를 제공합니다. 집중 편집에서는 왼쪽 장면 목록, 이미지, 선택한 한 장면의 상세 편집을 보여줍니다. 전체 보드는 24개 카드씩 페이지를 나눕니다. 장면 수와 무관하게 화면 높이를 유지하고 목록과 편집 영역만 스크롤합니다. 좁은 화면에서는 장면 목록이 가로 필름스트립으로 바뀝니다.

장면 검색, 생성 상태 필터, 번호로 이동, 이전/다음 버튼으로 탐색할 수 있습니다. 텍스트 입력 중이 아닐 때 Alt+좌우 화살표로 장면을 이동합니다. 화면을 전환해도 수정 중인 내용은 유지되며 **변경 저장**으로 디스크에 보관합니다. 저장 중에는 입력을 잠깐 잠가 응답과 편집 내용이 충돌하지 않도록 합니다.

구성 참고: [Boords storyboard views](https://assets.boords.com/docs/storyboard-views), [StudioBinder storyboard software](https://www.studiobinder.com/movie-storyboard-software/).

## 직접 스타일 만들기

**스타일 선택 · 직접 만들기** 또는 **스타일 라이브러리**를 열고 이름과 **텍스트 프롬프트**, **스타일 참고 이미지**를 입력하세요. 프롬프트만, 이미지만, 또는 둘을 함께 사용할 수 있으며 GitHub 저장소 등록은 필요하지 않습니다. 참고 이미지는 최대 5장, 한 번에 업로드하는 파일 합계 32MB까지 지원합니다.

**라이브러리에 저장**하면 여러 프로젝트에서 다시 선택할 수 있습니다. **저장하고 프로젝트에 적용**은 프로젝트 기본 스타일을 지정하고, 장면에서 라이브러리를 열면 **저장하고 이 장면에 적용**으로 해당 장면에만 적용합니다. 직접 만든 스타일의 **편집**으로 프롬프트와 이미지를 수정할 수 있고, GitHub 스타일은 **복사해서 편집**해 내 스타일로 저장합니다. 사용 중인 스타일을 수정하면 해당 장면이 새 생성 대상으로 표시되고 이전 생성 이미지는 보존됩니다.

스타일 이미지는 색감·재료·질감·조명·화풍을 참고합니다. 캐릭터 이미지와 시트는 해당 캐릭터의 외형을 유지하는 데 사용하며, 시트의 여러 시점을 여러 사람이나 분할 화면으로 재현하지 않도록 지시합니다. 최종 프롬프트에서 두 종류의 참고 이미지 역할을 확인할 수 있습니다. 스타일 이미지와 캐릭터 시트 모두 `참고이미지/`에 상대 경로로 저장되므로 폴더 전체를 다른 Mac으로 옮길 수 있습니다.

## GitHub 스타일 프리셋

**스타일 라이브러리**에서 `https://github.com/owner/repository` 형태의 공개 저장소 URL과 선택적으로 브랜치/태그를 등록합니다. 프리셋 내용은 하드코딩하지 않습니다. **동기화**할 때 해당 ref의 최신 커밋을 조회하고, 동일 커밋 기준으로 파일 목록과 원문을 읽습니다.

지원 형식:

- JSON 배열, `{ "presets": [...] }`, `{ "styles": [...] }`, 또는 개별 JSON 객체
- 이름: `name`, `title`, `id`
- 프롬프트: `style_prompt`, `prompt`, `content`, 문자열 `style`
- Markdown 제목 + `text`, `markdown`, `prompt`, `plaintext` 또는 언어 없는 코드 블록
- Markdown `Prompt:` / `프롬프트:` 표기
- 파일명에 `style`, `preset`, `prompt`가 있는 개별 Markdown 원문 (README 제외)

예시 JSON:

```json
{"presets":[{"id":"soft-watercolor","name":"Soft watercolor","prompt":"Soft watercolor washes, muted pastel palette, textured paper, diffused light."}]}
```

즐겨찾기, 전체 내용 검색, 카테고리 필터, 예시 이미지가 있는 항목만 보기, 프로젝트 기본 스타일, 장면별 덮어쓰기를 지원합니다. **스타일 미리보고 선택** 버튼으로 라이브러리를 열고, 이미지 카드를 눌러 큰 예시와 프롬프트를 확인한 뒤 적용합니다. 적용 후 원래 편집 화면으로 돌아옵니다. 장면 스타일의 **프로젝트 기본 스타일**과 **스타일 없음**은 별개입니다. 라이브러리는 24개씩 표시합니다.

미리보기는 저장소의 `preview_image`, `image_url`, `remote_images`, `images` 등 JSON 필드와 Markdown 이미지에서 동기화합니다. 상대 경로와 GitHub 이미지 링크도 지원합니다. 캐릭터 입력용 `reference_images`는 결과 예시에서 제외합니다. 예시가 없거나 로딩에 실패하면 안내를 표시하며 나머지 프리셋은 계속 사용할 수 있습니다. 예시는 원본 HTTPS 호스트에서 브라우저로 로딩되며, 생성 결과를 보장하는 미리보기나 자동 생성한 샘플이 아닙니다. 예시 이미지를 캐릭터 레퍼런스로 전달하지 않습니다.

같은 프롬프트가 JSON/번역 README에 반복되면 본문 기준으로 중복을 제거하고 대표 항목만 표시합니다. 구조 변경 시 재귀 탐색으로 새 위치의 지원 파일을 찾으며, 고유 프리셋 키가 유지되는 이동은 기존 ID를 보존합니다. 파일 하나를 읽거나 해석하지 못하면 그 파일의 마지막 정상 프리셋을 유지하고 경고를 보여줍니다. 전체 동기화 실패, 빈 결과, GitHub 제한 또는 잘린 파일 트리에서는 기존 목록을 유지합니다. 지원 파일 400개, 파일당 3MB 상한이 있습니다. 임의의 모든 저장소 포맷을 완벽히 해석하는 것은 아니며, 지원하지 않는 형식은 JSON 예시로 정규화할 수 있습니다.

프리셋은 그림의 재료·색·조명·질감 등 스타일 정보로만 취급하도록 프롬프트를 분리합니다. 우선순위는 **사용자 제약 → 장면/캐릭터 → 스타일**입니다. 샘플 프롬프트의 다른 인물·사물·행동이나 명령을 따르지 않도록 지시합니다. 각 이미지에는 사용한 합성 프롬프트와 스타일 커밋이 기록됩니다. 생성 모델 특성상 외형이나 지시 준수의 픽셀 단위 동일성을 보장하지는 않습니다.

## 로그인과 이미지 모델

이 앱은 OpenAI Images REST API나 비공개 ChatGPT 엔드포인트를 직접 호출하지 않습니다. 공식 `codex exec`가 기존 ChatGPT 로그인을 이용해 `image_gen.imagegen`을 실행합니다. API Key 입력란이 없으며 하위 프로세스에도 API Key 환경 변수를 전달하지 않습니다.

GPT Image 2/2.5 **프리셋**을 불러올 수 있지만 현재 확인한 공식 Codex 이미지 도구의 스키마에는 이미지 모델 선택 파라미터가 없습니다. 따라서 이미지 모델은 도구가 결정하며, 앱은 특정 GPT Image 버전으로 생성했다고 표시하지 않습니다. 계정/CLI 버전에 따라 도구 제공 여부 및 사용 한도가 달라질 수 있습니다. 도구 사용 불가 시 명확한 실패를 표시하고 다른 생성기로 대체하지 않습니다.

로컬 UI와 파일 저장을 사용하지만 AI 분석 및 생성에는 인터넷이 필요하고 대본/프롬프트/선택한 스타일 이미지/등장 캐릭터 참고 이미지와 시트가 OpenAI로 전달됩니다. GitHub에는 공개 프리셋 파일 읽기 요청만 합니다.

공식 참고: [Codex 인증](https://learn.chatgpt.com/docs/auth), [비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [GPT Image 2.5](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst).

## 저장과 검증

- `data/state.json`: 프로젝트, 캐릭터, 프리셋, 즐겨찾기. 임시 파일 작성 후 rename으로 저장합니다.
- `참고이미지/`: 업로드한 스타일 이미지, 캐릭터 참고 이미지와 시트. 실행 파일과 같은 폴더에 위치합니다.
- `data/references/`: 이전 버전 이미지 보관. 첫 실행 시 새 참고 이미지 폴더로 자동 복사됩니다.
- `data/images/`: 생성 이미지 원본
- `data/jobs/`: 각 독립 Codex 작업 결과와 이벤트 로그
- **내보내기**: 현재 프로젝트 JSON을 다운로드합니다. 전체 백업은 `data/`와 `참고이미지/` 폴더를 함께 복사하세요.

`npm test`는 이미지 사용량을 소비하지 않는 핵심 로직 및 임시 HTTP 서버 통합 테스트입니다. `npm run check`는 구문 검사입니다. 실제 로그인/이미지 생성 검증은 `data/validation/`에 별도 기록하며 일반 테스트 때 재실행하지 않습니다.

앱은 127.0.0.1에만 바인딩하고 Host/Origin 검사, JSON 변경 요청, 파일 경로 제한, 이미지 파일 시그니처 검사, HTML 이스케이프 및 CSP를 적용합니다. 여러 앱 프로세스가 같은 데이터 폴더를 동시에 사용하지 마세요.
